# Sensend 升级方案（完整版）

> 日期：2026-08-17
> 状态：待审阅（仅方案，未动代码）
> 范围：格式兼容性重构 + 悬浮球 + 主题色 + 性能优化 + 清理收尾
> 不含：图片传输（明确不做）、双向同步（明确不做）

---

## 一、产品定义锚定

**Sensend 是"速记→扔出去→在目的地改"的中转站。**

核心语义：
- 想到什么 → 记录 → @目标 → 发射 → 完事
- 不做档案馆（不建本地文档目录、不做双向同步、不做离线队列）
- 不做多目标同时分发（手动多次即可）
- 修改后形成新文档是产品语义的必然结果，解法是 UI 清晰反馈而非技术归档

所有升级决策以此为锚：凡增加"管理负担"的功能不做，凡提升"扔出去那一刻的体面度"的改进优先。

## 三、模块一：格式兼容性重构（核心）

### 3.1 目标

同一份笔记，在 Sensend 里长什么样，发出去就应该长什么样（或以明确的、一致的降级规则呈现），且四个出口的保真度对齐。

### 3.2 架构：IR + 能力矩阵 + 降级规则表

```
TipTap JSON
    │
    ▼  adapters/convert.rs（唯一遍历点，纯函数）
规范化 IR：Vec<IrBlock>
    │   块级：Paragraph / Heading(level) / Bullet(depth) / Ordered(depth) /
    │         Todo / Quote / Code(lang) / Table(rows) / Divider
    │   内联：Vec<Inline>，Inline = Text{content, marks} | Break
    ▼
┌───────────────────────────────────────────────────┐
│  apply_downgrade(ir, capabilities) → Vec<IrBlock> │  ← 降级规则表（集中一处）
└───────────────────────────────────────────────────┘
    ▼
┌─────────┬─────────┬─────────┬─────────┐
│ notion  │ flowus  │  lark   │  local  │   ← 薄映射层（无遍历、无递归）
│ ir→API  │ ir→API  │ ir→API  │ ir→md  │
└─────────┴─────────┴─────────┴─────────┘
```

### 3.3 能力矩阵（Rust 结构体）

```rust
pub struct PlatformCapabilities {
    pub supports_table: bool,
    pub supports_nested_list: bool,
    pub supports_todo_native: bool,    // 原生 todo 块 vs 降级
    pub supports_hardbreak: bool,
    pub supports_underline: bool,
    pub max_heading_level: u8,
    pub code_lang_format: CodeLangFormat, // 字符串 / 数字枚举
}
```

每个适配器在 `new()` 中声明自己的 capabilities，降级规则表查表执行，映射层不做任何判断。

### 3.4 缺陷修复清单（在 IR 层统一解决）

| # | 缺陷 | 修复方案 |
|---|------|---------|
| 1 | hardBreak 静默丢弃（Notion/FlowUs） | IR `Inline::Break` → 映射为 text 中的 `\n` |
| 2 | 嵌套列表拍平 | Notion/FlowUs：list item 携带 `children` 字段表达真嵌套；飞书：拍平但保文本不丢 |
| 3 | 飞书列表项只取首段 | IR 保留全部段落，飞书映射为多 text_run（`\n` 分隔） |
| 4 | 下划线本地导出丢失 | `<u>text</u>` HTML 兜底 |
| 5 | 表格单元格内联格式丢失 | IR 单元格保留 `Vec<Inline>`，Notion/FlowUs 走 rich_text |
| 6 | 飞书代码语言固定为 1 | 内置语言名→飞书枚举映射表（20 种常见语言） |
| 7 | 标题去重失效（>18 字） | extract_title 返回 `(display_title, full_text)`，去重用 full_text |
| 8 | 4 份平行转换代码 | IR 层收敛，彻底消灭 |

### 3.5 TaskList 启用

四个适配器的 taskList 转换分支已全部写好，只差编辑器入口：

- 注册 `@tiptap/extension-task-list` + `@tiptap/extension-task-item`
- BubbleMenu 增加待办按钮
- Markdown 粘贴支持 `- [ ]` / `- [x]` 解析
- 约 5 行配置 + 1 个按钮组件

### 3.6 测试与验收

- `fixtures/` 目录存放 8-10 个代表性 TipTap JSON（嵌套列表、表格+内联、hardBreak、待办、代码块、超长标题等）
- 每个映射层对每个 fixture 断言输出（cargo test）
- 能力矩阵从代码生成，杜绝文档滞后
- 验证链：`cargo test` + `cargo check`（MSVC 环境）+ `npm run build` + 真机走查

## 四、模块二：性能优化专项

### 4.1 设计原则

**用户感知链路**：按键 → 渲染（<16ms）、启动 → 可编辑（<800ms）、点击发送 → toast（<2s 网络延迟外）。

优化策略：**减少不必要的工作、推迟非关键工作、并行化可并行的工作**。

### 4.2 启动性能（冷启动到可编辑）

| 现状 | 优化 | 收益 |
|------|------|------|
| main.ts 同步 import ConfigWindow（约 50KB JS 立即解析） | 动态 `import()` + Vite manualChunks 分离 | 主窗口 JS 解析减少 ~30% |
| TipTap 编辑器在 setup 时立即初始化（含扩展注册） | 保持（编辑器是核心路径，不能延迟） | — |
| usePlatform onMounted 并行 IPC | 已优化，保持 | — |
| Rust 端 async fn + tokio::fs | 已优化，保持 | — |
| 窗口 `visible: true` 但内容未就绪 | 改为 `visible: false` + 前端 ready 后调 `show()` | 消除白屏闪烁 |

**vite.config.ts 新增**：
```js
build: {
  rollupOptions: {
    output: {
      manualChunks: {
        config: ['./src/ConfigWindow.vue', './src/composables/useConfig.ts'],
      }
    }
  }
}
```

### 4.3 输入性能（按键到渲染 <16ms）

| 现状 | 问题 | 优化 |
|------|------|------|
| onUpdate 每次按键执行 `doc.descendants` 遍历检测 mention | O(n) 遍历，大文档时 1-3ms | 改用 transaction 判断：仅当 `tr.docChanged` 且涉及 mention 节点类型时才遍历 |
| doSave 每次 `JSON.stringify(editor.getJSON())` | 大文档 2-5ms | 保持（800ms 防抖下频率极低，不构成瓶颈） |
| 字数统计防抖 300ms | 已优化 | 保持 |
| saveStatus 每次 onUpdate 设 'unsaved' | Vue 响应式触发重渲染 | 改为仅在状态实际变化时赋值（`if (saveStatus !== 'unsaved') saveStatus = 'unsaved'`） |

**mention 检测优化方案**：
```ts
// 替代 doc.descendants 全遍历
onUpdate: ({ editor: e, transaction: tr }) => {
  // 仅当 transaction 涉及结构变化时才检测 mention
  if (tr.docChanged && tr.steps.some(s => s.toJSON().stepType !== 'replace')) {
    // 此时才遍历
  }
}
```

### 4.4 发布性能（点击到完成）

| 现状 | 优化 | 收益 |
|------|------|------|
| stripMentions 递归遍历 JSON 树 | IR 层一次性处理（转换时跳过 mention 节点） | 减少一次遍历 |
| Notion resolve_target 已并行 | 保持 | — |
| append_children 多批次串行 | 保持（顺序保证，不可并行） | — |
| 飞书 token 缓存 2h | 保持 | — |
| HTTP timeout 30s | 缩短为 15s（用户等 30s 才看到错误体验差） | 错误反馈更快 |

### 4.5 渲染性能（丝滑体验）

| 项目 | 优化 |
|------|------|
| BubbleMenu 出现/消失 | tippy duration 150ms → 100ms（更快响应） |
| Toast 进出动画 | CSS transition 200ms，使用 `transform` + `opacity`（不触发重排） |
| 窗口显示/隐藏 | Tauri `window.show()` 前加 100ms fadeIn CSS 动画（消除突兀感） |
| 悬浮球弹出/收回 | 200ms ease-out scale + opacity 动画 |
| 发送按钮 loading | 微动画（脉冲或旋转），不使用骨架屏（内容太少不值得） |
| 编辑器滚动 | `will-change: transform` 仅在滚动时添加，避免常驻 GPU 层 |

### 4.6 内存与长时间运行

| 项目 | 优化 |
|------|------|
| TipTap 历史栈 | 默认 100 步，对速记场景足够；不修改 |
| tippy 实例 | 每次 mention 弹出创建/销毁——改为复用单例（减少 GC 压力） |
| HTTP 连接池 | OnceLock 全局复用，已优化 |
| Vue 响应式 | instances/platformTypes 数据量极小（几个对象），无优化空间 |

### 4.7 性能验收标准

| 指标 | 目标 | 测量方式 |
|------|------|---------|
| 冷启动到可编辑 | < 800ms | Performance.now() 打点 |
| 按键到渲染 | < 16ms（60fps） | Chrome DevTools Performance |
| 发送点击到 toast | < 500ms（不含网络） | 前端打点 |
| 内存占用（空闲） | < 80MB | 任务管理器 |
| 内存占用（编辑 1h） | < 120MB（无泄漏） | 任务管理器 |

## 五、模块三：悬浮球

### 5.1 交互定义

| 行为 | 说明 |
|------|------|
| 常态 | 桌面上始终显示悬浮球（半透明、微动画呼吸感） |
| 点击 | 恢复主窗口（等同当前快捷键唤起） |
| 拖入文档 | 高亮反馈 → 松开 → 解析内容 → 填入编辑区 → 自动聚焦 @mention → 用户回车发射 |
| 右键菜单 | 隐藏悬浮球 / 显示主窗口 / 退出 |
| 拖动 | 支持自由拖动（避免遮挡） |
| 隐藏 | 右键可隐藏，快捷键可恢复 |

### 5.2 拖入文档语义（选项 C）

```
拖入文件 → 解析 → 填入编辑区 → 自动聚焦 @mention → 用户回车发射
```

- 不自动发送（保留"看一眼再扔"的机会）
- 不建立本地文档目录（符合中转站语义）
- 支持格式：`.md`（@tiptap/markdown parse）、`.txt`（直接 setContent）
- 不支持：`.docx`（需额外依赖，暂不做）、图片（明确不做）

### 5.3 实现要点

- 新窗口：无边框、透明、置顶、click-through 关闭
- 尺寸：48x48px 圆形，带"发射"视觉隐喻（箭头/火箭图标）
- 拖放：Tauri `onDragDropEvent` 监听文件路径
- 呼吸动画：CSS `@keyframes` opacity 0.6→1 循环（3s 周期，不干扰注意力）
- 与主窗口联动：主窗口显示时悬浮球隐藏，主窗口隐藏时悬浮球显示

### 5.4 性能注意

- 悬浮球窗口独立于主窗口（不共享 WebView），避免主窗口渲染影响悬浮球动画
- 呼吸动画用 CSS 而非 JS（GPU 加速，不占主线程）
- 拖放检测用 Tauri 原生事件（不轮询文件系统）

## 六、模块四：主题色

### 6.1 方案：2 个精选主题

| 主题 | 定位 | 核心变量 |
|------|------|---------|
| 默认（当前） | 温暖绿，品牌色 | 保持现状 |
| 暗夜模式 | 低亮度、护眼、夜间 | bg: #1a1a2e, fg: #e0e0e0, accent: #4ecca3 |

**不做**：文艺风、谷歌科技风等风格化主题（与"中转站"的透明定位冲突）。

### 6.2 实现要点

- CSS 变量集中在 `vars.css`，主题切换 = 切换 `data-theme` 属性
- 配置窗口增加主题选择下拉菜单（不在主界面，避免干扰速记）
- 跟随系统暗色模式（可选，`prefers-color-scheme` 媒体查询）
- 悬浮球颜色跟随主题
- 不引入新依赖，不增加构建复杂度

### 6.3 性能注意

- 主题切换 = 修改 CSS 变量，无重渲染（浏览器原生支持）
- 不触发 Vue 响应式更新（纯 CSS 层面）
