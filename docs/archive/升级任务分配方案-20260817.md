## 四、执行顺序（总览）

```
阶段0  S0  git 基线加固                    ← 5 分钟          ✅
阶段1  S1  测试骨架（锁现状）               ← 安全网          ✅
       S2  IR 重构 + 六缺陷修复             ← 全程最难，最大块  ✅
       S3  飞书待办验证（顺手，lark 层刚写完）                 ✅
       ▶ 阶段提交点：cargo test + cargo check + npm build 三绿才准提交
阶段2  S4  性能高危项（mention 优化 / 窗口权限与收口）         ✅（含 B1）
       ▶ 阶段提交点：同上 + 手动验证 @mention 联动、窗口无白屏无权限报错
阶段3  S5  格式兼容性修复（入向粘贴规范化 + 出向表格/待办保真） ✅ 首批完成
       ▶ 阶段提交点：cargo test + npm build + 真机走查 GFM 表格粘贴四种来源
阶段4  B2→B3→B4→B5→B6→B7→B8→B9  普通任务严格串行  ◀ 当前位置（dumate 从这接手）
       ▶ 每个任务完成即构建验证一次，通过才进下一个
阶段5  全量验收（资深执行者）
       build-release.ps1 + cargo test + npm build
       + 四平台真机走查（全格式样例笔记：2层嵌套列表+表格含粗体+hardBreak+待办+代码块+下划线+超18字标题）
       + 发版 0.4.0（走 BUILD-GUIDE 第四节流程）
```

**顺序理由**：
1. **IR 先行**：所有格式类 B 任务（B1/B2/B3）写在新架构的映射层上，先重构避免返工；
2. **B 级严格串行在 S 级后**：避免多执行者同时改同一批文件打架；B 任务彼此无依赖冲突但仍串行（用户要求）；
3. **格式兼容性紧随 S4**：S4 窗口收口后，入向粘贴逻辑与出向 IR 层的改动互不冲突，可独立提测；
4. **主题色放 B 组靠后**：涉及两窗口同步，等 S 级全部完成后再做更稳妥；
5. **版本号最后升**：中途升级号会让半成品构建被误认为新版本。

## 五、全员通用纪律（写进每个任务的注意事项）

1. **构建唯一入口**：`powershell -NoProfile -ExecutionPolicy Bypass -File "scripts\build-release.ps1"`（见 `sensend/BUILD-ENV.md`）。普通终端直接 cargo/npm 必失败，报"MSVC 失败"是环境没加载，不是环境坏了。
2. **只改 `sensend/`**，严禁碰 `sensend-release/`（0.2.0 旧副本，改了白干）。
3. **验证三件套**：cargo check / cargo test（Rust 改动）、npm run build（前端改动）、跨端互验（改后端必须看前端表现，反之亦然）。
4. **禁止顺手重构**：只做任务单里的事，多余的一行不动。
5. **失败即停**：任务单里任何一步报错，停下来报告，不许带病继续。
6. **有疑问查审核结论**：《升级方案审核结论-20260817.md》第三节是纠错清单，第四节是补充建议，先读再动手。
